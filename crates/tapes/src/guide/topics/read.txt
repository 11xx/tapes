PAGE ONE RECORDING
  tapes read <id> --items 40 --bytes 1MiB --kind user,assistant --json
  tapes read <id> --before '<start>' --kind user,assistant --json
  tapes read <id> --after '<end>' --kind user,assistant --json
  tapes read <id> --head --kind user,assistant --json
  tapes read <id> --from-offset 0 --bound '<end>' --json
  tapes read <id> --before '<end>' --bound '<start>' --json

  tapes-recording-page/1 has flat items with start/end, kind, role, text, ts,
  native/request IDs, recorded model/effort and origin, full tool fields and
  native content. Item identity is start; native_id names a record/entry and
  can be shared by its parts. message_id groups Claude assistant message.id or
  user UUID, Codex message payload.id (absent on reasoning/tools), Pi entry ID,
  or OpenCode message ID. parent_id links Claude/Pi tree entries; OpenCode
  links the containing message to its parent message, usually the user prompt;
  Codex omits it. Store positions verbatim across
  processes. --after starts at the gap; --before ends there. Keep end to follow
  appends, start for older items. A Claude child is a separate --reference
  recording labelled parent::agent, with its parent linked.

  --head reads forwards from the beginning. File positions are canonical: one
  gap in one recording has one string. --from-offset reads forwards from a native
  byte offset: zero or immediately after a newline, within committed content.
  Construction inspects an anchor, never the prefix. Mid-record, unfinished and
  beyond-end offsets refuse as invalid-coordinate. --bound stops either direction
  at that gap, including filtered or itemless records; stop is bound and the page
  endpoint equals it exactly. Wrong-side bounds are invalid-position; foreign or
  replaced file bounds are replaced. File byte scanning stays inside the span;
  validating endpoints inspects their anchors and internal records separately.
  OpenCode supports head, tail and positional paging. Its adjacent part endpoints
  have distinct strings; native record coordinates and bounds are unsupported.

  Tool fields are name, status, title, metadata, caller, arguments and output.
  Search arguments carry the query/action. OpenCode title/metadata, Pi details
  as metadata and Claude caller share the native content allocation in Rust.
  Status is running, completed, failed, never-finished or unknown; native words
  remain in content. Calls have status only from their own recorded execution
  state: OpenCode parts or Codex runtime events. Claude/Pi and Codex response
  calls omit it; the result with the same call_id carries the outcome. Running
  means recorded running execution; results without an error are completed.
  OpenCode emits results only for completed/error parts; abandoned tools are
  single never-finished calls. OpenCode text/reasoning also exposes item status.
  Native content is complete and always present.

  --bytes counts native content once plus serialized item metadata, through a
  counting writer. Normalized text and tool projections share the payload
  budget; duplicate wire representations and the page envelope are additional.
  Oversized items refuse with needed, start and end: enlarge the budget or
  skip to end. --read-bytes caps source scanning: default 8MiB, maximum 64MiB.
  stop says why this page ended. Followers check pending/pending_bytes for
  unfinished input even with item, byte or scan stops. File reads add a <=1MiB
  identity header and one verification reread. Positions bind the inode and
  preceding newline and last min(record length,4KiB) bytes of that record;
  internal positions also bind their whole record. Anchors consume scan budget.
  Partial final lines wait for their newline. Nonzero pending_bytes names an
  unfinished file suffix; non-null pending names a database part. Consume page
  progress, then wait at that frontier for a source change. stop pending means
  this page ended at that frontier; diagnostics apply with other stops too.
  Untouched history is not pinned; a captured copy preserves it through edits.

  Claude records decode independently. Codex messages page by native content
  part; runtime mirrors remain distinct occurrences labelled runtime. Pi
  exposes its physical tree log, abandoned branches included, with parent_id;
  active-branch selection needs a whole-recording ancestry pass.

  OpenCode database parts page by time_created,id. Only text parts are prose;
  step/patch parts are unknown. Unfinished assistant text/reasoning and tools
  in pending/running state stop the stream only in the newest message, when it
  has neither a completion time nor an error. Tail ends below that frontier.
  Older unfinished parts publish as recorded with never-finished status; later
  turns remain visible. Published parts follow once; changed parts refuse.
  Each part is bounded by min(--read-bytes,4MiB), under an 8MiB transport cap.
  A tail uses at most three SQLite processes, a positioned page four, excluding
  discovery: capture/verify batches plus constant metadata/cursor queries.
  Native indexes cover session_id and message_id,id. SQLite scans/sorts the
  session for ordered pages; response bounds do not bound engine work.
  OpenCode API and supplied JSON/ZIP exports have no recording positions.

  Refusals are public library values. CLI JSON uses tapes-recording-error/1,
  refusal.kind and a nonzero exit for oversized, scan-budget, changed,
  replaced, unsupported, invalid-coordinate, invalid-position, invalid-input and
  unavailable cases.
  Scan-budget gives needed when a sufficient budget is known. Deleted files
  are replaced; internal truncation is changed. Busy/unreadable stores are
  unavailable; busy reads retain exit 75. Error JSON also carries retryable,
  equal to the library transient::is_transient(&error). Retry only when true;
  unavailable alone does not establish retryability. Rust Kind/Stop/Refusal are
  non-exhaustive; JSON Kind/Stop decode unfamiliar values as Unknown. Retain
  unknown kinds as non-prose. With an unfamiliar stop, consume returned items
  and save boundaries; continue if the requested boundary advanced, otherwise
  wait for a source change. End without pending input means caught up. Never spin on an unchanged
  boundary; an unfamiliar refusal needs an explicit recovery policy.
  Validate kinds, positions and budgets before discovering a session.
  Library callers build the non-exhaustive Limits with Default and with_items,
  with_bytes, with_scan_bytes, with_kinds and with_bound; additional options preserve callers.
