PRICE A CHANGE
  tapes usage --range main~5..main          What the last five commits cost, by commit, agent and role.
  tapes usage --branch feat-x --by merge    A branch's commits, live or merged and deleted, by the merge that landed them.
  tapes usage --commit SHA --explain        One commit, with the evidence behind each row.
  tapes usage --range A..B --detail         Every part of the view: unselected commits, evidence, sessions.
  git log --format=%H -5 | tapes usage --commits-from -  The commits a list names, one per line.
  tapes usage --pr 123                      A GitHub pull request, found through `gh`, by how it was merged.
  tapes usage <id> --by commit              One session divided across the repository's commits.
  tapes usage --window FROM..TO --by commit  What a window consumed, by commit.
  tapes usage --range A..B --prices FILE --json  tapes-change-usage/4, with list-price estimates.
  tapes usage --range A..B --evidence FILE  Sessions an evidence file names, placed by its records.
  tapes usage --commits-from LIST --evidence FILE --evidence-only  Only the sessions the file names.

  A change view answers what a set of commits cost from the recordings and
  the repository alone; it needs no ledger, hook or configuration. Run it
  inside the repository, or name one with --project. It reads the repository
  read-only through git, and the Claude, Codex and Pi recordings active from
  an hour before the earliest selected commit to half an hour after the
  latest. A change view reads each session whole more than once, which an
  OpenCode session refuses, so OpenCode sessions are listed under
  `membership.unreadable` and take no part.

  Each session is divided over every commit its evidence names, not only the
  selected ones, so what a session gives a commit does not change with what
  else is selected. A session active outside the interval is not read, so its
  inspection of a selected commit hours later is not counted, and a wider
  selection, reading a wider interval, can bring such a session in. A session
  whose directory no longer exists belongs to the repository only through
  another member that placed that directory, by a commit or a remote, so it
  is a member only when that member's interval is read too. The evidence
  comes in three tiers. A session that created a commit is bound to it.
  Bound means the session made the commit, not that it did the commit's
  work: a merge, a cherry-pick, a revert or a resumed rebase of another
  session's work creates commits too. An edit whose added lines the commit
  adds, or a stay in the commit's worktree or on its branch, is matched. A
  request near the commit's author time, or a command that names the
  revision (`git show`, `git diff`), is estimated. Each amount names its tier
  and its basis: span, event-window, working-stretch, inherited, even or
  following. A subagent is placed by its own evidence first, and inherits its
  parent's allocation for the rest. A parent a recording names, by a recorded
  launch or a `tapes-parent:` marker, makes the launched session a child in
  the same way when both are read (`tapes guide launch`).

  Rows are grouped by --by: commit, merge, agent (`harness:model#effort`),
  role, tier and session, commit, agent and role unless told otherwise.
  `merge` is the first-parent merge on the default branch that brought the
  commit; a commit made on that branch, as a fast-forward leaves it, is its
  own group. A role comes from the session's own evidence for the commit:
  `author` when it created the commit, made an edit the commit holds, or
  worked in its worktree; `reviewer` when it only inspected the commit;
  `proximate` when only time places it near. An inherited share takes its
  parent's role.

  Around the rows stand the other places a session's consumption went. The
  uncommitted buckets hold work after a session's last commit at a worktree
  and branch, such as a delegate's checks and report once it has committed.
  Unattributed parts carry a reason, such as `before first item` or
  `elsewhere`, time in a directory outside the repository: a session that
  steers the repository from another directory, without naming the
  repository's paths in `cd`, `git -C` or the paths its tools touch, leaves
  that time `elsewhere`. Both weigh most on interactive and orchestrating
  sessions; a session an evidence file names is placed by its records alone,
  with neither (below). Unselected holds what the same sessions spent on
  commits the view did not select; it is reported apart and kept out of the
  change's total. Per session and in the totals, rows, uncommitted,
  unattributed, unselected and labelled work (below) add up to the whole,
  and a recorded total no request explains stays apart under `unexplained`.
  Each request counts once, though a Claude lead's recorded total also counts
  its subagents' requests, and cache writes keep their 5-minute and 1-hour
  split, so --prices charges each at its own rate.

  --tiers bound,matched,estimated names the tiers that take part, all three
  by default. The named tiers place consumption together; what only the
  left-out tiers would place is unattributed as `tiers not asked`, naming
  them, so `--tiers bound` shows how much of a change rests on bound evidence
  alone: the commits sessions created, and the records an evidence file
  binds.

  A change view shows its selected rows by default: requests, disjoint
  tokens in compact figures such as `21.3M`, and with --prices the list
  price. An agent, role or tier the same on every row is printed once above
  the table, and a row leaves blank the leading cells that repeat the row
  above, so a commit's sha and subject head its rows once. Under the total, one line names what lies outside the selected
  commits (uncommitted, the unselected commits' shares, unattributed and
  labelled work, each only when non-zero) and one line the sessions' wholes:
  the total and the outside parts add up to the wholes. --detail adds exact
  counts, every dimension column and full subjects, the evidence behind each
  row by tier and basis, the tier list, unexplained parts, uncommitted work
  by place, unattributed work by reason, each unselected commit, labelled
  work, the sessions with what placed them, and the evidence files. --json
  answers tapes-change-usage/4 with the same split, `detail` saying which:
  without --detail it leaves out `rows[].evidence`, `uncommitted[].evidence`,
  `labelled[].evidence`, `totals.evidence`, `unselected`, `sessions` and
  `evidence`, and keeps every total, `totals.unselected` among them.
  --explain adds each row's evidence either way.

  Select commits with --commit (repeatable), --range A..B, --branch NAME (a
  live branch against the default branch, otherwise the merges whose subjects
  name it: `Merge branch 'NAME'`, or `merge(N): ...` where N is NAME or its
  last segment), --commits-from FILE|- or --pr N. A branch that is neither,
  a revision git does not know and an empty selection refuse, as do --family,
  --global and a session or window beside a selector. --explain lists each
  row's evidence: shas, paths and times, never transcript text.

  A pull request is priced by number with --pr N, which asks `gh pr view N
  --json ...` for the commits it listed and when it lived, and reads nothing
  else from the forge: tapes never runs `git fetch` and never writes to the
  repository. Without `gh`, or when `gh` fails (not authenticated, no GitHub
  remote, no such pull request), --pr refuses and names which; --commits-from
  prices the same work. The commits depend on how the pull request ended, and
  the output names the rule under `method`:
  - open, or closed unmerged: the listed commits that exist locally. The
    others are reported by sha under `missing`.
  - merged with a merge commit (two parents, the second reaching the listed
    commits): the listed commits. The merge commit authors nothing and is not
    selected.
  - rebase-merged (one parent, and the last n commits along first parents
    ending at the merge commit, n being the number listed, carry the listed
    subjects in order): those commits on the base branch.
  - squash-merged (one parent, not a rebase): the squash commit, and any
    listed commit that still exists locally.
  - none of these: the listed commits that exist locally, with the reason
    under `unrecognized`, such as a merge commit this repository never
    fetched.
  A squash or a rebase makes the pull request's work again under new shas,
  after it happened. So those commits also admit evidence over the pull
  request's lifetime, from its creation to its merge, widened by the usual
  hour before and half hour after; edits a session made on the branch days
  before link to the squash commit by their content digests, one tier down
  (matched, never bound). This is the one selection that adds evidence:
  `--commit SQUASH_SHA` alone uses the commit's own window and finds none of
  that work. A wider lifetime reads the recordings of a wider interval. The
  view reports the pull request's number, state, method, base and head names,
  title and lifetime. `--by merge` groups by the first-parent merge offline;
  --pr is the forge's view of the same grouping.

  Work from another forge is priced with --commits-from, which lists the
  request's commits: `git log --format=%H BASE..HEAD > commits.txt`, then
  `tapes usage --commits-from commits.txt`. The listed commits keep their
  own windows.

  Recordings alone give an estimate. A launcher, a ledger or a person who
  knows what a session worked on can make the figure exact with an evidence
  file (`tapes guide launch`): `--evidence PATH`, a file or a directory
  of them, repeatable. A session a `binding` or `event` record names is
  placed by those records alone, never by its recording's evidence, at tier
  `bound` for a bound record and `matched` for a declared one; a binding
  without a span takes the whole session. A record's work shares its part
  evenly among the commits of it the repository holds, and each such row
  keeps the work's label, so selecting one commit of a two-commit change
  takes half of it. Work of which the repository holds no commit, or that
  names only a label, is reported as `labelled` work, apart and out of the
  total like unselected commits. A named session whose work names a selected
  commit is looked up by harness and id wherever its recording began; one no
  installed store holds is listed unresolved and adds nothing. Its subagents
  and the sessions it launched inherit from it alone, and a `lineage` record
  makes its child a child of its parent where the child's recording names
  none. Recording evidence still places every session no record names.
  The role of a session placed by records is `reviewer` where its records
  say `reviewer`, and `author` otherwise. `evidence` reports the files and
  producers, the bindings and events that placed a session in the view,
  sessions looked up and unresolved, conflicts (a session whose recording
  shows it creating a commit no record naming it binds it to; the records
  still place it) and labels whose records disagree on their commits.
  --evidence-only keeps only the sessions the records name, each placed by
  its records alone, with no listing and no subagent or launched session, so
  a ledger's export reproduces the ledger's own figure.
