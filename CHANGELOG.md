## [2026.9.25] - 2026-09-25

### Added

- `--remote <ssh-destination>` on `list`, `show`, and `export` answers from
  a named replica's own `tapes` over ssh instead of this machine's stores.
  A remote session carries `source.replica`, its `live` state is only what
  the replica reported, and reads stay bounded on both sides. Every failure
  to reach or run the replica — no ssh, no `tapes` there, a schema this
  build does not read, an oversized or silent answer — is unavailable with
  its cause and its destination, never an empty listing and never a
  completed session. `export --remote` writes the bundle on the replica and
  prints each path as `destination:path`. The default `ssh` runs with
  `BatchMode=yes`, so a query never prompts; a program named through
  `TAPES_SSH` receives no added options.

- pi attributes its tokens and cost to the model and effort that spent
  them:
  each assistant message's recorded model, qualified by the thinking level
  in
  effect, folds into `by_model` rows carrying that row's tokens, cost, and
  request count, which `usage` and the usage object of `stats` report.

  `events --full-arguments` returns each tool call's complete recorded
  argument
  text in place of the 200-character preview, under the same members and
  schema
  version, so the commands a session ran are recoverable without reading
  the
  raw recording.

  `stats` reports the assistant-turn wall clock as count, median, p90, and
  max
  in `assistant_turns_ms`: one sample per source record carrying a model
  response — its text, its reasoning, or a tool call — measured from the
  previous turn's source record, so a response made only of reasoning and
  tool
  calls is measured too and a tool-result record is not. The stats view is
  tapes-stats/9.

- `export --evidence` copies a supplied conversation's record span and
  associated report members byte for byte into `<bundle>.evidence/`, named
  by SHA-256, with a `tapes-evidence/1` manifest of the input's digest and
  where every byte came from.

- Read evidence and export manifests name the reader build (`read.reader`:
  package, version, and the git revision it was built from), `tapes
  --version` names it too, and supplied-input reads carry the SHA-256 of
  each record span as `read.record_sha256`.

- `self` names the caller's own session wherever a session id is taken,
  including `--exclude self`, resolved from the session variable its
  harness exports and reported on stderr; the `--latest` note offers
  `--exclude self` when it picked the caller's own session.

- Each harness declares the turn kinds its records can evidence:
  `tapes-session/10`, `tapes-stats/6`, and `tapes-stats-summary/4` carry
  `kinds`, stats warns `kind-undeclared` for a turn outside the
  declaration, and a stats selection names the recordable kinds no session
  held.

- Read evidence counts the records a Claude, Codex, or pi read decoded and
  represented as no turn, by native type, as `unmapped.declined` or
  `unmapped.unrecognized`.

- `events --full` and `stats --full` read a whole Claude, Codex, or Pi
  recording instead of its bounded tail, reading it twice so tool calls
  pair without holding the file (34 MB for a 114 MiB Codex rollout, where a
  1 GiB bounded read peaks near 263 MB). `events --full` writes each event
  as it pairs, with `--tail`, `--name`, `--call-id`, and `--program`
  selecting as they do on a bounded read; `stats --full` counts every
  record with turn coverage `session`, including across a selection. Both
  refuse `--read-bytes`, supplied inputs, and OpenCode sessions.

- `export --full` bundles the whole Claude, Codex, or Pi recording instead
  of its bounded tail, streaming each file so memory follows one record (43
  MB for a 114 MiB Codex rollout). Its `.json` turns are the ones `show
  --full --json` writes and its `events` are paired across the whole
  recording; a recording appended to during the export is bundled as the
  first read saw it. The bundle `.json` is written compact. OpenCode,
  supplied inputs, and `--read-bytes` refuse `--full`.

- `usage`, `lineage`, and `child` accept `--full` to read a whole recording
  instead of its bounded tail, streaming record by record. `usage --full`
  counts every turn and folds tokens, cost, context window, quota, and
  model from every record, so its coverage is `session`. `lineage --full`
  names children spawned before the tail window. `child --full` streams a
  Claude subagent recording and checks every record against its parent.
  `--full` conflicts with `--read-bytes` and refuses supplied inputs.

- `show --full` reads whole OpenCode sessions from both the database and
  the `opencode2` API, past the 1,000-message cap of a bounded read,
  writing turns page by page. Its read evidence counts messages
  (`coordinate_domain: opencode-message`). Database part text stays cut at
  4,000 characters (2,000 per tool field) and the cuts are reported under
  `truncation.source`; an API message larger than the 8 MiB transport bound
  stops the read with an error naming its position.

- `show --full --json` writes the tapes-session/8 object turn by turn, with
  read evidence covering the whole recording and the content inventory
  summed as turns stream.

- `show --full` streams whole Codex and Pi recordings, classifying Codex
  user turns and choosing Pi's active branch from a first pass that keeps
  only operator messages or entry ids and parents.

- `show --full` streams a whole Claude recording past the file-tail bound,
  writing each turn as it is read so memory follows one record; `--tail`
  and `--exchange` apply, and other harnesses refuse it by name.

- `list --here` and `--project` report sessions they left out because their
  recorded directory no longer exists, as `unplaced` in JSON and a `Not
  placed:` line naming `--global --directory`.

- Added `--read-bytes` to show, export, events, lineage, stats, usage,
  brief, endings, and child: installed recordings are read through a
  caller-set tail between 64KiB and 1GiB (default 4MiB). Every byte flag
  now accepts sizes such as `64k`, `512MiB`, or `64KB`; a bare or `iB` unit
  is binary and a `B` unit is decimal.

- Added `--exchange` to `show` and `export`: only operator and assistant
  turns, each with its timestamps and original ordinal; every omitted turn
  is counted by kind under `projection`, and `--tail` counts exchange
  turns.

- Project nested invocation declarations and bounded artifact observations
  without executing or counting nested script text as independent calls.

- Read supplied Perplexity conversation envelopes with bounded query/answer
  normalization, explicit metadata and timestamp coverage, and workbook
  exclusion.

- Read caller-supplied OpenAI and ChatGPT Exporter files, directories, and
  ZIP archives through bounded normalized views with opaque occurrence
  coordinates, explicit gaps, and structured report references.

- Read Claude subagent transcripts, usage and ending evidence by parent
  session and exact child reference, retaining separate identity and source
  coverage.

- Read Claude and Codex history through bounded backward pages and
  snapshot-bound continuation cursors; search historical turns and recover
  recorded model observations with explicit page budgets and coverage gaps.

- Aggregate recorded tool calls, results, pairing, errors and durations
  across an explicitly selected session set, retaining each read coverage
  and failure.

- Select a session by exact recorded title across single-session commands,
  with project scope, ambiguity refusal, and explicit incomplete-lookup
  diagnostics.

- `tapes brief <session>` renders what a cold continuation needs from the
  recording alone (`tapes-brief/1`): the working set (directory, git head
  and branch, whether the directory still exists), the ending facts, calls
  without a result and children without a recorded outcome as handles to
  reattach, a bounded tail of operator and assistant turns, and usage; it
  reads no journal and judges nothing.

- `tapes stats <session>` aggregates one session in a bounded pass
  (`tapes-stats/1`): turns by kind, tool calls and results by name with
  pairing, errors, and timed durations, recorded spans and gaps, usage with
  cache ratios named by the counters they divide, lineage counts, and
  warnings naming every way the figures are incomplete; facts only, no
  judgment.

- `tapes endings` reports one bounded record per selected session
  (`tapes-endings/1`): the last turn and its kind, the last operator and
  assistant turns, structural facts established from turn kinds and
  tool-event pairing only (operator turn after assistant, control or notice
  turn last, call without result, results without narration, assistant
  close), what makes them incomplete, a stable source reference, lineage
  counts, and an optional bounded text tail; scope and activity filters
  apply before any read.

- `tapes usage` over a selection (the listing flags) sums recorded counters
  and costs by `--by harness,model,variant,directory` groups
  (`tapes-usage-summary/1`), stating per group how many sessions carried
  each counter and how many are recorded totals, summed over the session,
  summed over a read window, or unaccounted.

- `tapes lineage <session>` reports the parent, children, and fork a store
  records for a session (`tapes-lineage/1`): Claude subagent transcripts
  joined to their `Agent` calls, Codex child rollouts joined by agent path
  to `spawn_agent` and agent-status records, OpenCode
  `parent_id`/`parentID` and fork columns, pi `parentSession`; unresolved
  references are kept and marked, and no child transcript is read.

- Every turn carries `kind` (operator, assistant, reasoning, tool, control,
  ambient, notice, unknown) filled only from harness-native fields, so a
  session ending on a Claude `/exit` or a task notification is no longer
  read as an unanswered operator prompt; `show` and `.trace.md` head
  non-operator user turns `user/<kind>` and `.context.md` drops control,
  ambient, and notice turns.

- Claude sessions carry tokens and cost from the newest `cost-state` record
  or a per-request sum deduplicated by request, pi sessions sum per-message
  usage on the active path, and every session with counters carries
  `accounting` stating whether the figures are a recorded total or summed
  requests and whether they cover the session or only the read window.

- `tapes events <session>` projects typed tool calls and results
  (`tapes-events/1`) with exact call/result pairing, durations, and named
  incompleteness at read boundaries; `--name` and `--call-id` filter after
  pairing. `tapes-session/1` output is unchanged.

- `list --since` and `--until` filter sessions by `last_activity_at`
  (half-open, RFC 3339 or a date) before the per-harness limit, `--sort
  newest|oldest` orders deterministically with id and harness tie-breaks,
  and `tapes-list/1` reports `sort` and the applied `activity` window.

- `list --search <text>` matches the last 32 normalized turns of each
  candidate before `--limit`, so a limit never hides a match. A raw-tail
  prefilter and capped parallelism keep a full-scope search practical; a
  candidate whose bounded read fails is reported in `unsearched` rather
  than silently treated as a non-match. `derived_title_truncated` tells a
  JSON consumer whether a title ended or was cut.

- `show` names the newest trailing record — its kind and timestamp — for a
  session whose last store record is not a rendered turn. Verified for the
  Claude, Codex, and pi backends; a backend with nothing to report omits
  the field rather than inventing one.

- `tapes list --model <substring>` and `--directory <substring>` filter a
  listing in the library, ahead of the per-harness bound; a session whose
  model or directory is absent never matches.

- `tapes show` names the store's activity stamp when it is later than the
  newest turn rendered, so `list` and `show` no longer disagree silently
  about whether a session has done anything since.

- Optionally annotate list and show results with the present-tense working
  or idle state reported by harness-status, while keeping volatile state
  out of export bundles.

- `tapes show --latest` and `tapes export --latest` resolve the newest
  session of the project holding the current directory, so a caller needs
  no session id; `--exclude <id>` passes over sessions it already holds,
  `--project <path>` scopes elsewhere, and `--global` drops the scope.
  `--here` now means the whole project — every worktree of its repository —
  and applies before `--limit`, so a bound spent on other projects can no
  longer empty a scoped listing. Listings report `scanned` and
  `scan_truncated`. A transcript larger than the bounded read window now
  still reports the directory it ran in.

- `docs/formats/` documents each harness's store: file layout, line and
  payload types, and the quirks a reader must handle.

- `tapes export` writes a three-file rescue bundle — `.context.md` for
  reading whole, `.json` for querying with `jq`, `.trace.md` for grepping
  reasoning and tool chronology — atomically, into `--bundle <dir>` or
  `/tmp`.

- `tapes list` now merges bounded sessions from every available harness,
  and `tapes show` resolves exact or unambiguous session prefixes,
  including OpenCode sessions retrieved through its standalone API.

- Added bounded Claude, Codex, and pi session backends behind a shared
  normalized trait, including malformed-line and abandoned-branch notes;
  OpenCode remains an unavailable seam for its API slice.

- Define the versioned normalized session and transcript model in
  `tapes-core`, including omission-preserving optional metadata, token and
  cost accounting, UTC activity timestamps, and bounded-read truncation
  state.

- Add the installable tapes CLI workspace with list, show, and export
  command skeletons.

### Changed

- Reserve collision-free export sibling namespaces and clean only this
  invocation's outputs when evidence publication fails.
- Project completed-only Codex runtime items as same-record call/result
  pairs with recorded arguments.
- Carry degraded latest and scoped unplaced diagnostics through CLI views
  and JSON.
- Publish as tapes-cli with binary tapes; make ZIP support explicitly
  optional and default-off with self-contained package tests.

- `tapes page`, `history-search`, and `metadata` read only each page's own
  byte range for Codex recordings, with no opening or newer-records context
  read: about a third of the previous physical reads per page on large
  rollouts. Turn kinds are unchanged, since each Codex turn is typed from
  its own record. `context_bytes`, the `context` read range kind, and the
  `opening-and-newer-provenance` projection option are removed; the schemas
  are `tapes-page/5`, `tapes-history-search/5`, and
  `tapes-metadata-history/5`.

- `show` and `export` take `--only <KIND>` and `--omit <KIND>`, repeatable
  or comma-separated, to keep or drop turns by kind; omitted turns are
  counted by kind under `projection`, which reads `{"kept": [...],
  "omitted": {...}}` in `tapes-session/9`. `show --exchange` is shorthand
  for `--only operator,assistant`. `export --exchange` is removed: a
  bundle's `.context.md` is always the exchange and holds exactly the turns
  `show --exchange` returns.

- Supplied inputs: a conversation record without a native ID no longer
  makes lookup by ID refuse. ID lookup refuses only when a gap could cover
  an unread ID; title lookup still refuses on any gap.

- Usage summary schema version 2 partitions compatible accounting domains
  and omits mixed-domain token and cost sums while retaining session counts
  and coverage.

- `tapes show --latest` names the session it picked and the `--exclude`
  that reaches the one before it; the truncation note and the `list`
  scan-truncated footer carry their next action.
